Scoring engine design

This runs 100% locally in JavaScript — no network calls, no API, no server. It's scoped to one job: parse plain text the way an ATS parser and a fast recruiter skim would, and return a single verdict. The engine:

  • A fixed scoring rubric. Five weighted checks — keyword match (40%), section structure (15%), contact info (10%), quantified achievements (15%), and formatting/parseability risk (20%) — combine into one 0–100 score, so results are consistent and explainable rather than a black box.
  • Keyword extraction tokenizes the job description, strips common stopwords, and keeps meaningful terms (skills, tools, titles), then checks each against the resume text for a match/missing split.
  • Structure detection uses header pattern matching (e.g. "Experience", "Education", "Skills" and common variants) to confirm the standard sections an ATS looks for are present and labeled.
  • Quantified impact detection scans bullet-style lines for numbers, percentages, dollar amounts, and multipliers, since measurable outcomes are what separates a strong bullet from a vague duty statement.
  • Edge-case handling — if the resume or job description is empty, too short, or clearly not resume/job content (or a PDF that read in as binary noise), the engine returns a validation message instead of a fabricated score.
  • Tone lock: professional, direct, no fluff, no emoji, feedback framed as fixes not criticism.

Why the UI choices fit the use case

The visual language is built around the actual mechanic of an ATS: a machine "scanning" a document. The scan-line sweep in the logo and the loading state, the monospace "data readout" typography for the score and keyword tags, and the dark, instrument-panel palette all come from that idea rather than a generic chat layout — because this tool's value is a verdict, not a conversation.

The score is a circular dial (glanceable, familiar from health/credit-score UIs) paired with a pass/borderline/fail badge, so the headline result is visible in under a second. Keyword matches render as small tags in two colors (found vs. missing) so users can see gaps against the job description at a glance, without reading paragraphs.

Extending this engine

  • Real AI scoring: swap the local heuristics for a Claude API call (via a backend that holds the key) for nuanced, context-aware feedback beyond pattern matching.
  • Real PDF/DOCX parsing: add a library like pdf.js or mammoth.js so file upload works reliably instead of relying on pasted text or plain .txt.
  • Memory: store past scans in localStorage so a user can track score improvement across resume versions.
  • Tailoring: let users pick an industry or seniority level as a form field, and use it to weight which keywords/format norms matter most.
